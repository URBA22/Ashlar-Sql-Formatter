# Changelog

## 0.1.0

Initial release.

- Document and range formatting for SQL files, with Format on Save support.
- Hand-written tokenizer and layout engine, no external formatting dependency.
- A complete code style model across 135 settings, organised into Case, Tabs and
  Indents, Wrapping, Queries, Expressions, Code and DDL sections. Every setting
  that describes layout changes the output; the style reference page is
  generated by running each one through the formatter.
- Column-accurate indentation, so continuation indents, river alignment and
  column alignment all land where they should.
- Every value of every enum setting has behaviour of its own, checked by the
  build: the parenthesis placements, the wrap modes, `auto` commas and the
  collapse modes are all distinct rather than aliases of one another.
- A Style Reference panel (`SQL Formatter: Open Style Reference`): a live
  settings editor that shows each setting's before and after, reflects the
  values in force for the User, Workspace or folder scope, and saves each change
  immediately. Hovering a value previews it before you commit.
- Column alignment for `AS`, `=`, `ASC`/`DESC`, `THEN`, and DDL types, defaults
  and nullabilities; right-aligned clause keywords for river style.
- T-SQL by default; PostgreSQL, MySQL, SQLite, Oracle and ANSI dialects.
- Clause-aware layout for `SELECT`, joins, `CASE`, CTEs, `MERGE`, `BEGIN`/`END`
  blocks, `IF`/`ELSE` bodies and `GO` batches.
